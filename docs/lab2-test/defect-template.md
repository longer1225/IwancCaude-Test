> 用法：复制下面整块，粘进 Linear 的 Description，再把 `<>` 里的内容替换掉。

## 标题格式


## 严重度判定口径（照《测试计划》9.2，别自己发明）

| 级别 | Linear Priority | 判定标准 | 例子 |
|---|---|---|---|
| 致命 | Urgent | 系统崩溃 / 不可启动 / 数据损毁 | daemon 起不来、会话文件被清空 |
| 严重 | High | 核心功能不可用且无替代方案 | 任务无法取消、审批被绕过 |
| 一般 | Medium | 功能局部异常，有规避路径 | 某个模式下状态显示不对 |
| 轻微 | Low | 界面提示、文案微瑕 | 报错文案缺字段名 |

## 建单后必做的三件事

1. 把 `IWA-xx` 号回填到用例表 `02_用例表` 的“缺陷号”列（统计与追溯靠它）；
2. 在缺陷单里保持状态流转：`Backlog → Todo → In Progress →（回归验证）→ Done`；本 workspace 没有 `In Review` 状态，用 `Todo` 暂存待验证；
3. 关单前必须有**三联回归**记录（见 `regression-guide.md`），没有证据不许拖 `Done`。
