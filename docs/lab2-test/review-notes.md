| # | 检查项 | 通过标准 | 现状 / 意见 |

## 二、开发方在评审会上可能被问的 6 个问题（提前备好答案）

| 问题 | 回答要点 |
|---|---|
| 为什么没有 SRS？ | 计划 3.1 已声明以 README + 学习图 + `WIRE_PROTOCOL` + 代码为基线并锁版本；我用《需求基线》把它们落成 8 字段口径 |
| 那 5 个缺陷怎么来的？ | 是 `BUG-TASKS.md` 预置的演练基线（计划 2.4），用于走通“复现—修复—回归”流程，不计入新增缺陷统计 |
| 为什么先修了缺陷？ | 修复提交在 `main` 之后、已打 tag；被测基线仍是 `b3c4363`，缺陷在该版本仍可复现，回归时切 tag |
| 覆盖率为什么只有 42%？ | `config.py` 是配置读写大户，基线 42%；补测清单与 5 条建议已交测试负责人（计划 4.1 R5 归测试负责人） |
| 30 多条命令为什么不测？ | 计划 5.2 明确排除（Git 面板全量、SSH/GitHub 真实集成、插件市场等），我在 4.2 节逐条写了依据与处理方式 |
| 谁来关单？ | 测试负责人（计划 2.2）；开发方只提交复现与自测证据，不自行关单 |
