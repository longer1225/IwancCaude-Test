# 回归指南：三联回归怎么做、记录写在哪里

> 依据《测试计划》9.3：**开发每提交一次缺陷修复，测试人员必须执行“三联回归”**——
> 对应复现用例 + 模块相关单元测试 + 核心主链路冒烟；结果附日志记入缺陷单评论区。
> 原则上要求修复后**连续两次验证稳定通过**（或关键单测与集成全绿）方可置 `Done`。

---

## 一、三联回归是什么（三条都跑，缺一条不算）

| # | 内容 | 怎么跑 | 通过标准 |
|---|---|---|---|
| 1 | **对应复现用例** | 照缺陷单“复现步骤”重跑一次 | 原来失败的步骤现在符合期望；无新的报错 |
| 2 | **模块相关单元测试** | `uv run python -m pytest tests/unit/test_<模块>.py -q` | 该文件全绿；全量不低于 `1235 passed / 5 skipped` |
| 3 | **核心主链路冒烟** | `uv run iwan core status` → `uv run iwan ping` → 一次离线对话（假 Key + 死端点） | status 为 running、ping 返回 pong、对话事件序列完整 |

> 如果修复动了协议模型（`core/bus/*`），第 2 条要加跑 `scripts/gen_protocol_doc.py` 的产物检查，确认 `WIRE_PROTOCOL.md` 已重生成。

---

## 二、龙嘉璟（开发）自测要交的东西

修复提交时，在缺陷单评论区贴下面这段（填完再发）：

```markdown
### 开发自测（修复提交 `xxxxxxx`）
- 复现验证：<命令/步骤> → 修复前 `<错误输出>` / 修复后 `<正确输出>`
- 新增用例：`tests/unit/test_xxx.py::test_yyy`（N 条），已跑：`pytest ... -q` → N passed
- 全量单测：`uv run python -m pytest tests/unit -q` → 1235 passed, 5 skipped
- 离线主链路：`uv run iwan ping` → pong；`iwan core status` → running (127.0.0.1:7438) pid=xxxx
- 白盒根因：`文件:函数:分支` + 触发条件
```

## 三、测试负责人（刘显尘）验证后要交的东西

```markdown
### 三联回归（第 N 次）
- ① 复现用例：FP-09-E-02 → 通过 / 不通过（附输出）
- ② 模块单测：`tests/unit/test_permissions_manager.py` → 42 passed
- ③ 主链路冒烟：ping=pong，一次离线对话事件齐全
- 结论：通过（第 1/2 次）→ 可置 Done / 退回 Todo（原因：...）
```

连续两次通过后，测试负责人把单子拖到 `Done`，并把 `IWA-xx` 记进《缺陷报告》的“回归情况”列。

## 四、记录表在哪

- **Excel**：`test-cases.xlsx` 的 `09_回归记录` 表——已按 `IWA-5—IWA-9` 预填 5 行，只填“结果/证据/日期”；
- **Linear**：缺陷单评论区（正式留痕，评审看这个）；
- 两处不一致时以 **Linear 为准**，Excel 是给《缺陷报告》汇总用的。

## 五、12-10 第一轮回归：龙嘉璟要跑的用例

按《测试计划》7.1，开发方协助执行约占总执行量 10% 的**核心链路回归**用例。当前 43 条用例，10% ≈ **4—5 条**，建议就取下面这 5 条（都是 P0 核心链路、且与已修缺陷相关）：

| 用例编号 | 功能点 | 为什么选它 | 预计耗时 |
|---|---|---|---|
| `FP-01-B-03` | daemon 生命周期（边界/幂等） | 覆盖 BUG-2 的双实例防误杀 | 10 min |
| `FP-03-E-02` | 异常连接（连到外部实例） | 覆盖 BUG-3 的 `core.info` 识别 | 10 min |
| `FP-06-E-02` | 模型预设（错配告警） | 覆盖 BUG-1/BUG-4 的窗口与厂商错配 | 10 min |
| `FP-09-E-02` | 工具审批（断连） | 覆盖 BUG-5 的断连不阻塞 | 15 min |
| `FP-14-C-01` | 可观测性（trace 改道） | 确认证据链本身可用 | 10 min |

> 这 5 条跑完，正好把 5 个已修缺陷各回归一次，且都属“核心链路”，符合计划对开发方回归范围的要求。
